# КЛИНИКА РЯДОМ - ПОЛНЫЙ ОБЗОР АРХИТЕКТУРЫ

Этот документ объясняет внутреннюю логику проекта целиком, чтобы внешний агент (Claude Code / любой LLM-агент) понял структуру и мог помогать дорабатывать, стабилизировать и улучшать код.

---

## 1. ЧТО ЭТО ЗА ПРОДУКТ

«Клиника Рядом» - Telegram-клиника с 6 «врачами-методистами» (НЕ живыми врачами, а ИИ-ассистентами). Каждый врач - ОТДЕЛЬНЫЙ Telegram-бот. Есть 7-й бот - главный (входная точка, оформление абонемента, личный кабинет).

Бизнес-модель:
- Абонемент 1690 руб/мес → доступ ко ВСЕМ 6 врачам сразу.
- Бесплатный пробный период 7 дней (лимит 10 обращений/день/на КАЖДОГО врача отдельно).
- Платный: лимит 35 обращений/день/на врача.

Важно: все 6 врачей + главный бот работают на ОДНОМ коде (`bot.py`) и ОДНОЙ базе данных (PostgreSQL `clinic_ryadom`). Бот выбирается по токену, переданному аргументом: `python bot.py main` / `python bot.py terapevt` и т.д.

## 3. АРХИТЕКТУРА И ПОТОК ДАННЫХ

### 3.1. Главный бот (@Clinic_ryadom_bot, tool="main")
Точка входа пользователя. Что делает:
1. Приветствие + два обязательных юридических документа (мед дисклеймер + политика конфиденциальности) → кнопка «Я ознакомился и согласен».
2. После согласия → меню со списком 6 врачей (кнопки-ссылки ведут на ботов врачей) + кнопки «Оплатить абонемент» и «Личный кабинет».
3. Личный кабинет: статус абонемента, остаток триала, карточка клиента, кнопка продления.
4. Оплата пока ЗАГЛУШКА (CloudPayments ещё не подключена, доступ активируется вручную).

### 3.2. Боты врачей (tool="terapevt", "psiholog", ...)
Каждый врач = свой бот, но один и тот же код (`make_doctor_handler(key)`).
Поток пользователя у врача:
1. Согласие (дисклеймер + политика) - обязательно.
2. Проверка доступа: триал ИЛИ активный абонемент.
3. Заполнение карточки клиента (обязательно ПЕРЕД общением): имя, возраст, пол, хронические заболевания, жалобы.
4. Общение: текст / фото / голосовые (голос распознаётся Whisper через Groq).
5. Проверка дневного лимита (10 триал / 35 платно на врача).
6. История сохраняется НАВСЕГДА, каждый врач помнит свой диалог отдельно.

### 3.3. Модель обработки сообщений врача
```
handle_doctor (текст)
  → ensure_user
  → проверка согласия
  → проверка доступа (trial/active)
  → проверка карточки клиента
  → проверка дневного лимита
  → сохранить сообщение пользователя в БД
  → получить ответ врача (ai.ask_doctor с историей + карточкой как контекст)
  → сохранить ответ + инкремент лимита
  → отправить ответ

handle_doctor_photo (фото)
  → аналогичные проверки
  → скачать фото из Telegram (байты)
  → ai.analyze_photo (Gemini Vision) → описание
  → передать описание врачу в контекст → ответ

handle_doctor_voice (голос)   [ДОБАВЛЕНО 12.08.2026 - фикс бага]
  → проверки
  → _transcribe_voice (Whisper/Groq) → текст
  → подставить распознанный текст в message.text
  → вызвать handle_doctor (обычный поток)

handle_other (стикер/документ/видео) → вежливая заглушка
handle_card (текст во время заполнения карточки) → ведёт квест карточки
```

## 4. КЛЮЧЕВЫЕ ПОНЯТИЯ И ЛОГИКА

### 4.1. Доступ (access_info)
```
active  → есть активная подписка
trial   → идёт бесплатный период (7 дней от согласия)
expired → триал истёк, подписки нет
none    → ничего нет
```

### 4.2. Триал (в db.py: mark_consent, start_trial, trial_info)
- Стартует один раз, при первом согласии.
- Длится config.TRIAL_DAYS (7) от момента старта.
- Не возобновляется, если уже был.

### 4.3. Лимиты (в db.py: get_today_count, increment_today_count)
- daily_limits таблица: PK (user_id, doctor_key, day).
- Триал: 10/день/врача. Платный: 35/день/врача.

### 4.4. Карточка клиента (db.py + handle_card)
- Поля: имя, возраст, пол, хроника, жалобы.
- Обязательна ПЕРЕД общением с любым врачом.
- Хранится в таблице client_card (см. schema... ВНИМАНИЕ: в schema.sql, который я видел, НЕТ таблицы client_card - она создаётся где-то ещё или была добавлена позже. Проверить! См. раздел «Известные слабые места»).
- Передаётся врачу как system-сообщение в начале контекста.

### 4.5. История (chat_history)
- Роль: user / assistant.
- По user_id + doctor_key - отдельная история на каждого врача.
- photo_file - file_id фото, если было.
- ПРИНЦИП: каждое сообщение пишется в БД СРАЗУ, до вызова нейросети. Даже если нейросеть упадёт - диалог не теряется, следующая попытка продолжит с места остановки.

## 5. НЕЙРОСЕТИ (ai.py)

### 5.1. DeepSeek (текст)
- Модель: deepseek-chat.
- Прямой вызов API через urllib (НЕ через SDK).
- Ретраи: 3 попытки, backoff 2^n сек, таймаут 45 сек.
- На 429 останавливается сразу.
- Если не ответил → вежливый fallback (FALLBACK_REPLY), бот НЕ молчит и не падает.
- Ключ: ~/.openclaw-neuro/.deepseek_key

### 5.2. Gemini Vision (фото)
- Модель: gemini-flash-latest.
- Кодирование фото в base64, inline_data.
- Ретраи: 3, backoff, таймаут 50 сек.
- Ключ: ~/.openclaw-neuro/.gemini_key

### 5.3. Whisper / Groq (голос) [добавлено 12.08.2026]
- Модель: whisper-large-v3-turbo, language="ru".
- Ключ: ~/.openclaw-neuro/.groq_key
- Скачивает голосовое из Telegram (download_to_memory), отправляет в Groq.

### 5.4. Системный промпт врача (build_system_prompt)
- Собирается из роли врача (config.DOCTORS[key]["role"]).
- Включает: живую дату, стиль «живого врача» (эмпатия, вопросы в конце, без канцелярита), красные флаги (скорая при тревожных симптомах).
- ОБЯЗАТЕЛЬНО: отвечать без звёздочек и длинных тире.

## 6. БАЗА ДАННЫХ (PostgreSQL clinic_ryadom)

Таблицы (schema.sql):
- users: user_id (PK), username, first_name, created_at, lang
- consent: user_id (PK), policy_agreed, disclaimer_agreed, agreed_at, trial_started_at, trial_end_at
- subscriptions: user_id (PK), plan, date_start, date_end, status, paid, created_at
- chat_history: id, user_id, doctor_key, role, content, photo_file, created_at
- daily_limits: (user_id, doctor_key, day) PK, count
- payments: id, user_id, amount, currency, status, provider, provider_tx, created_at
- admins: user_id (PK), role
- + (в коде db.py используется таблица client_card: user_id, full_name, age, gender, chronics, complaints, completed, updated_at)

Подключение: db.py DB_DSN = "host=127.0.0.1 dbname=clinic_ryadom user=clinic_ryadom password=clinic_ryadom_2026"

## 8. ИЗВЕСТНЫЕ СЛАБЫЕ МЕСТА И ЧТО ДОДЕЛАТЬ

🔴 Высокий приоритет:
1. **CloudPayments НЕ подключена** - оплата заглушка. Пользователь нажимает «оплатить», создаётся pending-подписка, доступ активируется ВРУЧНУЮ. Нужна реальная интеграция: создание платежа, webhook подтверждения, автоматическая активация при успешной оплате.
2. **Таблица client_card не в schema.sql** - схема БД неполная. Надо добавить CREATE TABLE client_card в schema.sql, чтобы БД можно было пересоздать с нуля.
3. **Мессенджер Max** - отдельный объём: нужны верификация ИП, токен через @MasterBot, своя интеграция Bot API (пока только Telegram).

🟡 Средний приоритет:
4. **Токены ботов лежат открытым текстом** в secrets/*.token с правами 600. Надёжнее через env/менеджер секретов, но для текущего масштаба ок.
5. **Нет авто-продления напоминания** - пользователь не получает push-уведомление за пару дней до конца триала/подписки. Можно добавить cron / планировщик.
6. **error_handler** перехватывает ошибки, но нет алерта владельцу (Артуру) в личку при сбое. Можно добавить уведомление в Telegram владельцу.
7. **Голос распознаётся синхронно** через Groq - при длинных голосовых может быть задержка. Оптимизация: тайм-ауты, обработка длинных аудио, плейсхолдер «распознаю...» (уже есть).

🟢 Низкий / идеи:
8. Возможность очистки истории пользователем (уже есть clear_history в db.py, но нет кнопки в боте).
9. Удаление аккаунта (запрос на удаление данных - для GDPR-подобной политики).
10. Мультиязычность (сейчас только RU).
11. Админ-панель: просмотр пользователей, подписок, ручная активация доступа.
12. Уведомления о сбоях владельцу.

## 9. ЧТО ДЕЛАТЬ АГЕНТУ (РЕКОМЕНДАЦИЯ ДЛЯ КЛОДА)

1. Прочитай все файлы в этой папке: bot.py, config.py, db.py, ai.py, schema.sql, TZ_TRIAL.md.
2. Если просят доработать - не переписывай файлы целиком, делай точечные правки (edit).
3. После любых правок: проверь синтаксис python (ast.parse), перезапусти нужные systemd-сервисы.
4. При проверке страниц/структуры следуй существующему стилю (одна БД, один код, точечные правки).
5. Модель по умолчанию для проекта: DeepSeek (дёшево и быстро). Sonnet/opus - только по явной команде владельца.

Делегирование от владельца: «когда основной ассистент работает нестабильно - агент может помочь с кодом клиники, понять логику и предложить улучшения».
