## 3. Функциональные требования

### 3.1 Текстовый перевод
- Пользователь пишет фразу, бот сам определяет язык (сербский / русский / английский).
- Логика направления:
  - сербский -> русский
  - английский -> русский
  - русский -> сербский
- Рядом с переводом показывается флаг направления (🇷🇸 -> 🇷🇺 и т.д.).
- Русский -> сербский дополнительно даёт кнопку "🇬🇧 Перевести на английский".

### 3.2 Определение языка (автодетект)
Приоритет маркеров (в этом порядке):
1. Сербские слова (кириллица и латиница с диакритикой š, ž, ć, č, đ, nj, lj).
2. Спецбуквы сербской кириллицы (љ, њ, џ, ћ, ђ).
3. Сербские латинские диакритические буквы.
4. Русские спецбуквы (ъ, ы, э, щ, ё, й, ю, я, ц, ш).
5. Русские стоп-слова.
6. Доля кириллицы > 50% -> русский.
7. Английские стоп-слова.
8. По умолчанию -> сербский.

Все решения логируются в таблицу lang_detection_log (для отладки).

### 3.3 Голосовой ввод (STT)
- Пользователь шлёт голосовое, бот отвечает: "🎙️ Распознаю и перевожу на русский..."
- Транскрипция: Whisper large-v3-turbo через Groq (language=hint: sr).
- Определение языка по ответу Whisper (serbian/serbo-croatian -> sr, english -> en).
- Переводится на русский и озвучивается.
- Вывод: "🎙 Распознано: <текст> ... <перевод>".
- Если голос уже на русском - перевод не нужен, бот так и сообщает.

### 3.4 Перевод по фото (OCR)
- Пользователь шлёт фото с текстом.
- Распознавание текста: Gemini Vision (gemini-3-flash-preview), возвращает только текст.
- Далее тот же конвейер: определение языка + перевод + озвучка (если не русский).

### 3.5 Озвучка (TTS)
- Google Translate TTS (server-side), ffmpeg конвертация mp3 -> ogg (opus, 48k, atempo 0.85).
- Используется для фото-перевода (озвучка результата на русском).

### 3.6 История диалога
- SQLite (translator_history.db): таблицы dialog_history и lang_detection_log.
- Бот помнит последние ~12 сообщений на чат для связности перевода (контекст в DeepSeek).
- /clear - удалить историю (сейчас просто сообщает об удалении).

### 3.7 Производительность (ГЛАВНЫЙ ПРИОРИТЕТ)

Бот обязан переводить голосовые быстро и стабильно. Медленная работа - критичный дефект.

#### 3.7.1 Обязательная схема: АГЕНТ-РОУТЕР на входе аудио-конвейера

Встроенный лёгкий агент-классификатор в начале обработки голосового.
Задача агента: мгновенно (без тяжёлого API) решить, какой язык распознан и
куда переводить. Агент НЕ отдельный бот и НЕ отдельный процесс - это лёгкий слой
логики внутри того же бота.

Работает так:
1. Аудио -> Whisper (Groq) распознаёт текст (1-2 сек).
2. Агент-роутер по тексту решает язык: сербский / русский / английский
   (лёгкая эвристика + короткий быстрый вызов, без громоздкого детекта).
3. Направление (жёстко, без вариантов):
   - сербский -> русский
   - английский -> русский
   - русский -> сербский (+ кнопка "🇬🇧 Перевести на английский")
4. Перевод - быстрая лёгкая модель перевода (не тяжёлая, жёсткий таймаут).

Целевая скорость ответа на голосовое: 2-4 секунды суммарно.

#### 3.7.2 Императивные требования к скорости

1. Общий ответ на голосовое - НЕ дольше 3-5 секунд с момента записи.
2. Промежуточный статус "🎙️ Распознаю..." - мгновенно, до обработки.
3. Перевод - лёгкая быстрая модель с жёстким таймаутом, без долгих ожиданий
   и без ретраев, которые тянут время.
4. Кэш перевода повторяющихся фраз в БД.
5. НЕ тянуть полную историю диалога (12 сообщений) в каждый перевод,
   ограничить контекст или отключать по ситуации.
6. ffmpeg - одна быстрая перекодировка, без цепочки лишних операций.
7. Параллельная обработка: следующие сообщения не ждут завершения текущего.

ВАЖНО: работа над скоростью - не косметика, а основной критерий приёмки.
Бот для живого общения, ждать 30+ секунд нельзя.

#### 3.7.3 Языки - ТОЛЬКО три

Поддерживаются ТОЛЬКО сербский, русский, английский. Никаких других языков.
При неопределённости (не смог понять язык) агент-роутер честно возвращает
распознанный текст как есть и уточняет, вместо того чтобы переводить в кашу.

## 4. Команды

- /start - приветствие и справка по возможностям.
- /sr - режим: сербский -> русский.
- /ru - режим: русский -> сербский (+ озвучка).
- /en - режим: английский -> русский.
- /clear - очистить историю диалога.

## 5. Технологический стек (ТЕКУЩЕЕ РЕШЕНИЕ)

- Язык: Python 3.
- Telegram Bot API: прямые HTTP-запросы (requests), long polling getUpdates.
- Перевод: **DeepSeek (текущее решение)** - таймаут 60s, retry-логика.
- STT: Groq Whisper large-v3-turbo.
- OCR: Google Gemini Vision (gemini-3-flash-preview).
- TTS: Google Translate TTS + ffmpeg.
- Хранение: SQLite (история + логи определения языка).
- Ключи/токены: в /root/.openclaw/workspace-neuro/secrets/ и ~/.openclaw-neuro/.

**Примечание:** ТЗ v1.2 требует быструю лёгкую модель вместо DeepSeek для достижения целевой скорости 2-4 секунд. Текущая реализация использует DeepSeek. Переход на быструю модель требует отдельного решения.

## 6. Обработка ошибок

- Retry-логика для GET/POST (до 3 попыток, exponential backoff).
- Retry на getUpdates (до 3 попыток).
- Ошибки перевод/STT/OCR возвращаются пользователю человеческим текстом.
- Логирование через logging.
