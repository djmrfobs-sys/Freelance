# Шаблон: self-test / health-check для каждого продукта

Добавлять в конвейер как обязательную часть Этапа 3 (сборка) для каждого нового бота/продукта.

## Требование
Каждый продукт, который выпускает конвейер, должен иметь одну простую команду или endpoint,
подтверждающий не просто "процесс запущен", а "функциональность реально работает".

## Для Telegram-ботов
Реализовать команду `/health` (или `/ping`), которая:
- Отвечает мгновенно с текущим статусом (uptime, версия, последняя успешная операция)
- Проверяет доступность ключевых внешних зависимостей (БД, внешние API), если они есть
- НЕ требует прав администратора — fleet-health.sh должен уметь дёрнуть её автоматически

Пример минимальной реализации (Python/aiogram-стиль, адаптировать под стек):
```python
@dp.message(Command("health"))
async def health_check(message: types.Message):
    status = "OK"
    checks = []
    try:
        # проверка БД, если есть
        await db.execute("SELECT 1")
        checks.append("db: OK")
    except Exception as e:
        status = "DEGRADED"
        checks.append(f"db: FAIL ({e})")
    await message.answer(f"Status: {status}\n" + "\n".join(checks))
```

## Для веб-сервисов
Стандартный `/health` или `/status` endpoint, возвращающий JSON `{"status": "ok", "checks": {...}}`

## Интеграция с fleet-health.sh
После того как у ботов появятся health-команды — fleet-health.sh можно расширить:
вместо только `systemctl --user is-active` — дополнительно слать тестовое сообщение `/health`
через Bot API и проверять, что пришёл осмысленный ответ, а не только что процесс жив.

## Правило для конвейера
Добавить в Этап 5 (релиз) product-conveyor-SKILL.md пункт: "Health-check команда реализована
и протестирована" как обязательный чекбокс перед сдачей.
