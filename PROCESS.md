# PROCESS.md — Конвейер от ТЗ до релиза

Этот процесс — **обязательный стандарт** для ЛЮБОГО нового продукта, бота или крупной фичи.

Триггеры: "сделай бота", "новый проект", "запусти продукт", "с нуля", крупная фича.

---

## Этап 0 — Проверка перед стартом

- Есть ли аналог в `zavod/` или среди 15 действующих ботов?
  - Если да → предложи переиспользовать код/цех, не писать с нуля
- Проверь `knowledge/artur/` на релевантные наработки

---

## Этап 1 — Сбор ТЗ (GATE)

**Пока открыт хотя бы один значимый вопрос → не переходи к архитектуре.**

- Структурированное интервью:
  - Цель продукта
  - Аудитория
  - Платформа
  - Ключевые сценарии использования
  - Ограничения (бюджет/сроки/интеграции)

- **Разделяй два типа недостающих деталей:**
  - **Мелочи** (структура проекта, обработка ошибок, логирование, стиль кода) → решу сам по дефолту
  - **Значимое** (фичи, пользователь, интеграции, definition of done) → спрашу

- Предлагай пункты, которые пользователь мог упустить:
  - Обработка ошибок на уровне бизнес-логики
  - Лимиты
  - Что при сбое внешнего API
  - Нужна ли админка/аналитика
  - Definition of done

- **Оформи ответ двумя блоками одним сообщением:**
  1. "Что решил сам по умолчанию" (список принятых решений, можно поправить)
  2. "Что мне нужно от тебя" (2-4 значимых вопроса, не больше)

- **Финальное подтверждение:**
  - Зафиксируй ТЗ-документ
  - Получи явное "да, фиксируем"
  - Без подтверждения → GATE закрыт, дальше нет

---

## Этап 2 — Архитектура

- Опиши структуру проекта (модули, файлы, зависимости)
- Выбери цех (`zavod/0X`) или обоснуй новый
- Примени фирменный стиль KISELEVY CREO, если есть UI/тексты/визуал

---

## Этап 3 — Сборка

- Генерируй код модуль за модулем, не одним файлом
- После каждого модуля → короткая сверка с ТЗ
- **Чекпоинты при долгой сборке:**
  - Короткие статус-отметки ("архитектура готова, начинаю сборку", "модуль X собран")
  - Не молчи до финала
- **При неясности:**
  - Если решается дефолтом → решу сам, зафиксирую в отчёте
  - Если меняет архитектуру → остановлюсь и спрошу

---

## Этап 4 — Самопроверка

- **Reader-проход:** перечитай весь код против ТЗ
  - Все пункты покрыты?
  - Edge-cases?
  - Обработка ошибок?
  - API недоступность?
  - Захардкодины секреты?

- **Обязательный реальный прогон:**
  - Запусти проект
  - Прогони ключевые сценарии из ТЗ
  - Не считай готовым только по коду
  - Используй systematic-debugging при ошибке

- **Verification-before-completion:**
  - Сырой вывод реального запуска
  - Каждый пункт ТЗ работает

---

## Этап 5 — Релиз

- Финальный чек-лист:
  - Запуск/деплой (systemd unit, если бот)
  - Логирование настроено
  - README готов
  
- Итоговая сводка для пользователя:
  - Что сделано
  - Где лежит
  - Как запустить/остановить

---

## Правила

### GATE система
- На Этапе 1: открытый значимый вопрос → не переходи дальше
- Явное подтверждение ТЗ → только потом архитектура

### Не додумывай молча
- Что меняет функциональность/бизнес-логику/объём → спрашивай
- Мелочи (структура проекта, стиль) → решай сам

### Отчётность
- **Сырой вывод команды, не пересказ**
- Особенно для: бэкапов, удаления файлов, secrets, чисел
- Без вывода → утверждение, которое нельзя проверить

### Verification-before-completion
- Задача не закрыта без реального прогона
- Только с практическим подтверждением, что работает
