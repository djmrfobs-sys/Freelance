# Конвейер: от ТЗ до релиза

Единый пошаговый конвейер для ЛЮБОГО нового цифрового продукта (бот, сайт, нейропомощник, воронка) на нейрозаводе. Использовать КАЖДЫЙ раз, когда начинается новый продукт с нуля или крупная фича. Не изобретать процесс заново - идти по чек-листу.

## ПРАВИЛО ОТЧЁТНОСТИ (всегда)
Когда отчитываюсь о проверке (файлы существуют, тест прошёл, числа сходятся) - прикладываю СЫРОЙ вывод команды, а не только пересказ своими словами. Пересказ без вывода - это утверждение, которое нельзя проверить. Особенно строго для: бэкапов, удаления файлов, работы с secrets/ключами, любых чисел, которые Артур может захотеть перепроверить.

## ПРИНЦИП (Артур, 13.08.2026)
«Делаем грамотно, стабильно и без глюков. Лучше перепроверяй себя несколько раз, чтобы всё было чётко.»
Если на любом этапе не хватает информации от Артура - остановись и спроси. Не додумывай молча то, что меняет архитектуру или поведение продукта.

## Правила завода (обязательно)
- Модель по умолчанию: DeepSeek (экономия, ключ ~/.openclaw-neuro/.deepseek_key). Haiku - только если DeepSeek не вывозит, и с согласия Артура. Sonnet/Opus - только по явной команде.
- Секреты/токены - в secrets/, НЕ зашивать в код.
- Код работающих ботов НЕ переносить (systemd с абсолютными путями) - меняется реестр, не пути.
- ВАРИАНТ Б в текстах: «Этот инструмент для вас, если...» + «Мы...». Без «Закрывает» и «Что делаем».
- В текстах: только обычный дефис, без длинных тире и звёздочек.
- Генерация изображений: никогда не менять лица/тела людей (только фон/одежда/ракурс/поза).

## Этап 0 - Проверка перед стартом
- Есть ли уже похожий продукт в zavod/ или среди 15 действующих ботов? Если да - предложи переиспользовать код/цех, а не писать с нуля.
- Проверь knowledge/artur/ на релевантные наработки по теме.

## Этап 1 - Сбор ТЗ (НЕ начинать код, пока не пройден)
- Веди структурированное интервью: цель продукта, аудитория, платформа, ключевые сценарии, ограничения (бюджет/сроки/интеграции).
- Сам предлагай, что пользователь мог упустить: обработка ошибок, лимиты, логирование, поведение при сбое внешнего API, нужна ли админка/аналитика.
- Зафиксируй финальный ТЗ текстом (по шаблону projects/zavod/template/TZ.md) и получи явное подтверждение «да, фиксируем», прежде чем идти дальше.
- ПЕРВЫЙ ОТВЕТ Артуру после ТЗ: вывод по инструментам/архитектуре/срокам/рискам.

## Этап 2 - Архитектура
- Опиши структуру проекта (модули, файлы, зависимости) ДО генерации кода.
- Выбери, в какой цех (zavod/0X) продукт ложится логически, или обоснуй новый цех.
- Примени фирменный стиль KISELEVY CREO (скилл kiselevy-creo-style: палитра, тон, оформление; скилл kiselevy-creo-content-designer: референсы например, не менять лица) для UI/текстов/визуала.
- Заведи карточку в memory/NEURO_FACTORY_REGISTRY.md до старта кода.

## Этап 3 - Сборка
- Генерируй код по согласованной архитектуре, модуль за модулем, а не одним большим файлом.
- После каждого модуля - короткая сверка с ТЗ: не отклонились ли.
- Боты: Python + aiogram 3.x. Сайты: HTML/CSS (стиль KISELEVY) или Vercel (скилл deploy-to-vercel).

## Этап 4 - Самопроверка (reviewer-проход)
- Отдельным проходом перечитай весь код против исходного ТЗ: все ли пункты покрыты, нет ли забытых edge-cases.
- Проверь базовое: обработка ошибок, поведение при недоступности API, нет ли захардкоженных секретов.
- Прогони на крайних вводах: пустая строка, длинный текст, эмодзи.
- Синтаксис: python -c "import ast" (для питона).

## Этап 5 - Релиз
- Финальный чек-лист: запуск/деплой (systemd unit, если бот; Vercel, если сайт), логирование настроено, есть базовый README.
- Проверить, что сервис активен, лог без критичных ошибок.
- Сообщи Артуру итоговую сводку: что сделано, где лежит, как запустить/остановить, что может сломаться.

## Этап 6 - Память + приёмка
- Записать в memory/YYYY-MM-DD.md: что сделано, статус, что проверить.
- Обновить memory/NEURO_FACTORY_REGISTRY.md.
- Обновить memory/inbox.md (вычеркнуть/перенести задачу).
- Прогнать тест-сценарий из ТЗ, дать Артуру (или клиенту) протестировать.

## СУБАГЕНТЫ-ЦЕХОВИКИ (переиспользуемая схема)
Для больших задач запускать через sessions_spawn с чётким брифом (цель/выход/где писать/как проверить):
- Аналитик: парсинг соцсетей (Apify), разбор ниши/конкурентов, аудит.
- Код-инженер: пишет и тестирует ботов/скрипты/сайты по ТЗ; отдаёт код + тест.
- Контент-продакшн: тексты, посты, сценарии Reels, озвучка (TTS/STT) по стилю KISELEVY.
- Проджект-менеджер: сводит всё в готовый продукт по ТЗ, следит за сроками, готовит отчёт.
Короткие задачи - делать самому, без субагента. Запускать цех, только когда задача большая и параллелится. Я координирую и ПЕРЕПРОВЕРЯЮ результат перед сдачей.

## ЧЕК-ЛИСТ ПЕРЕД СДАЧЕЙ (все пункты обязательны)
1. Синтаксис проверен, сервис запущен, логи чистые.
2. Протестированы успех + сбои и крайние вводы.
3. Секреты - в secrets, в код не попали.
4. Документация (README) есть.
5. Карточка в реестре NEURO_FACTORY_REGISTRY.md обновлена.
6. Принцип «не додумывать молча» соблюдён.
Если хоть пункта нет - НЕ сдавать, доделать.
