# Несколько ботов — как добавить второго (база знаний Завода Джарвисов)

Источник: статья kb.mcdenil.com, прислана Артуром 24.08.2026.

## Суть
К одному агенту можно подключить несколько Telegram-ботов: общая память, один характер, каждый ведёт свой разговор. «Вторая дверь в ту же квартиру».

## Не путать
- Мульти-бот = один агент, общая память, бесплатно и сразу.
- Второй агент = своя память, свой сервер (для другого клиента) — заводится отдельно.

## Зачем второй бот
- Работа в две руки: пока первый занят большой задачей — пишешь второму параллельно.
- Распределение задач: первому разработку, второму контент.
- Общий мозг: второй знает всё, что знает первый (память, проекты, характер).

## Как добавить
/settings → 🤖 Мои боты → ➕ Добавить бота → инструкция @BotFather (2 мин) → прислать токен → агент проверит и добавит → перезапуск на пару секунд.

## Важные правила
- Каждый бот новый и отдельный (нельзя тот же дважды).
- Отвечают только владельцу (чужой доступа к памяти не получит).
- Удалить: Мои боты → 🗑.
- Второй бот умеет всё то же: голос, фото, документы, меню команд, настройки.
- Память общая, разговор у каждого свой.
- Двумя ботами память разом лучше не грузить: одно обновление может потеряться (резерв MEMORY.md.bak).

## Сколько ботов заводить
- Спящий бот ест копейки.
- Активная задача = ~0.5-1.5 ГБ памяти сервера.
- Ориентир: 2 работающих разом — комфортно почти на любом сервере; 3+ тяжёлых задач разом — увеличивать сервер.
- Пример: первому боту «задеплой лендинг», второму параллельно «заголовки для поста» — оба помнят проект и стиль (память общая).

## Применение к нашему заводу
У нас это уже есть: 15 ботов в одном gateway (общая память OpenClaw, параллельные диалоги). Его «несколько ботов у одного агента» = наш gateway с 15 ботами.
Разница: у него добавление через /settings, у нас через systemd + конфиг.
Взять на заметку: держать backup памяти (у него MEMORY.md.bak) — у нас тоже стоит периодически бэкапить memory/.
