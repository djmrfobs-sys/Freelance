# Бэкапы — что сохранять и как не потерять (база знаний Завода Джарвисов)

Источник: статья kb.mcdenil.com, прислана Артуром 24.08.2026.

## Суть
«Что не в GitHub — того не существует». Сервер = рабочий стол, GitHub = сейф. Восстановление из GitHub — одна команда, без бэкапа — невозможно.

## Что бэкапить (по важности)
- Критично: MEMORY.md, SOUL.md, USER.md, проекты ~/projects/, .env (ключи — записать отдельно!).
- Важно: GOALS.md, knowledge/.
- Желательно: memory/ (последние 30 дней), кастомные скиллы.

## Что НЕ бэкапить
Daily notes старше 30 дней (автоочистка), /tmp/, node_modules/ (npm install), .agent/bot/ (приезжает с обновлениями).

## Бэкап через git
cd ~/workspace && git add -A && git commit -m "backup: дата" && git push. Для проектов — аналогично по одному.

## Автобэкап
«Каждый вечер предлагай запушить изменения в GitHub» — запомнит и напомнит.

## Ключи API
.env НЕ пушить (небезопасно). Записать список ключей отдельно (менеджер паролей) — при потере сервера вводить заново через /settings.

## Восстановление
Переустановка → bootstrap → «склонируй workspace из GitHub» + проекты по одному.

## Применение к нашему заводу
У меня бэкап уже настроен (сегодня): скрипт scripts/backup_memory.sh (копирует memory/ + DNA-файлы) + cron раз в день, 14 копий. GitHub djmrfobs-sys для push. Могу добавить git push в GitHub для полного бэкапа workspace + проектов — скажи, настрою.
