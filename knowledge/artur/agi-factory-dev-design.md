# Разработчик и Дизайнер — рабочий продукт без найма (база знаний Завода Джарвисов)

Источник: статья kb.mcdenil.com, прислана Артуром 24.08.2026.

## Суть
Разработчик пишет рабочий код, Дизайнер делает интерфейс с характером. Правильный порядок: сначала стиль → потом код.

## Разработчик (fullstack-developer)
Лендинги, боты, скрипты, REST API, интеграции. Стек: React, Next.js, Node.js, PostgreSQL, MongoDB, Supabase, Vercel, Docker, GitHub Actions.
Каждый раз выдаёт пакет из 5 частей: файловая структура, полный код, зависимости (npm/pip), переменные окружения, инструкция по запуску.

## Дизайнер (frontend-design)
Интерфейс с характером, не шаблонный (уходит от purple-on-white). Сначала направление (брутальный минимализм, ретрофутуризм, редакционный стиль...), потом детали (шрифт, цвет-доминанта, анимации, компоновка). Каждый дизайн уникален.
Совет: описывать настроение, а не цвет («строго, с характером», а не «хочу синий»).

## Фоновая команда усиливает
Веб-специалист читает сайты по ссылке (референс для дизайнера, API для разработчика). Сервер-специалист диагностирует после деплоя.

## Что умеют / не умеют
- ✅ Рабочий код с нуля, уникальные интерфейсы, интеграции по API.
- ⚠️ Сложные проекты — итерационно (часть → проверить → продолжить); дизайн требует твоего «ок».
- ❌ Деплой без подтверждения (RED-операция), тест на реальных устройствах.

## Совет
Сначала стиль → потом код. Каждый шаг = отдельный /reset (дизайн → /reset → код → /reset → деплой).

## Применение к нашему заводу
- Разработчик = Claude Code на сервере (настроен сегодня) + скиллы кода (python-sdk, javascript-sdk, building-inferencesh-apps).
- Дизайнер = скиллы (landing-page-design, logo-design-guide, book-cover-design, image_generate).
- Деплой = Vercel + GitHub (настроены сегодня).
- Правило «деплой с подтверждением» = мой P1 (необратимые действия без ОК).
